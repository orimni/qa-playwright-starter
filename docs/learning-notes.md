# 学习笔记：先建立测试思维

## 测试用例的最小结构

| 要素 | 本项目示例 |
| --- | --- |
| 前置条件 | 服务启动，用户位于登录页 |
| 操作 | 输入错误账号并提交 |
| 预期结果 | 页面显示“用户名或密码错误” |
| 证据 | 断言通过；失败时保留截图和 trace |

## 这三个断言为什么重要

- `toBeVisible()`：确认用户能看到关键页面，而不是只确认 URL 变化。
- `toHaveText()`：确认业务结果，而不是只确认按钮点击成功。
- `toHaveJSON()`：确认 API 的数据契约，防止后端悄悄改变字段。

## 第一个练习

把 `tests/ui/login.spec.ts` 中的正确密码改成错误密码，运行 `npm test`，观察失败报告；然后恢复密码，再运行 `npm run report` 查看 HTML 报告。这个过程就是最小的“修改—执行—观察—修复”闭环。
